# 回放榜计分与复现

## 模型与五场对照

首页使用一份固定题单，每个参赛组合独占一行，逐场明细使用同一组题号。当前包含五场比赛、每场 BP 前后两题。完整题号、发布包指纹和选取依据来自[当前题单](suites/featured-five.json)。本地保留历史运行，旧题单的结果可以从各自的运行记录查看。

## 计分与名次

每题分别预测蓝方获胜和蓝方在 15 分钟领先的概率。两个事件使用相同权重，reward 为 `1 − ((p_win − y_win)² + (p_15 − y_15)²) / 2`。组织者使用发布包中的真值重算每项误差，并核对题面与冻结输入的 SHA-256。BP 前和 BP 后分别在自己的五道题上计算平均分。

- 排名要求受控运行按同一发布包、相同题号、后端和协议完成十份有效交卷。每个比较组按十题平均 reward 降序，四舍五入到十二位小数后同分并列，例如 1、1、3。
- 每个模型和 harness 在同一条件下展示一轮实际运行。优先选计划十题且交齐的运行；有多轮时按开始时间取最近一轮，旧目录缺少开始时间时采用目录时间。没有完整运行时优先按当前题单的覆盖情况选择，列出已交题数和状态，名次留空。逐场数据都来自该行指向的同一轮记录。
- OpenRouter 免费模型和 DeepSeek 官方模型均可通过受控网关参评。Cursor 厂商服务在独立赛道展示。固定响应、离线基线和环境预检归入技术记录。历史报告的完整数据集评分和不同选题的统计仍可离线复算。
- 一轮中已启动但失败的题计零，未启动与成功交卷分别计数。Brier 均值仅使用有效交卷。新比赛、不同协议或不同历史边界的成绩需使用相应的题号和版本复核。

## 收录一次新运行

1. 用 `./bench release --version <新版本>` 生成不可变归档和清单，保留原始来源及时间。参赛侧只持有当题快照。历史按先前局号、公开时刻和所选时点截断。lobby 在第一手 BP 公开时关窗，draft-lock 在实际开局时关窗。实盘成绩还需要独立的赛前提交回执，回放榜无法追溯证明模型此前没见过赛果。
2. 在组织者控制的环境执行 `./bench e2e --release datasets/replay-v3 --harness codex --model deepseek-v4-pro`。省略选题条件会运行当前十题，使用 `--all` 可运行全量 198 题，指定 `--series`、`--game` 或 `--phase` 产生相应子集。记录 CLI 版本、后端、模型 ID、提示词、预算、提供方及可用的用量信息。旧协议归入 `suite-v1`。更改工具权限、上下文或预算时，应为新协议记录独立的 `protocol_sha256` 并保留对应配置。
3. 新 CLI 需接入本仓库受限 worker、完成原生工具轨迹和隐藏标签探测，并使用同一评分器。受控与厂商通道的权限不同，按其实际运行模式注册到对应赛道。不要把 fixture 或供应商代填的预测转换成受控成绩。
4. 将完整输出保留在本地看板扫描范围。检查题号、提交时间、release 归档 SHA-256、快照和题面指纹，以及报告记录的真实模型。重复运行保留独立目录与所有失败，未完成的运行用原配置 `--resume --out <原目录>` 继续。组织者不得删掉低分尝试或复制某轮来改变权重。

## 信任边界与异议复核

本地榜信任组织者、只读发布包和被扫描的运行目录。SHA-256 与重算可以发现错包、错题和算错分，不能证明谁执行了 CLI、模型权重来源、申报者保留了全部尝试，或宿主从未被改写。模型可能记得公开比赛。跨组织正式比赛需另行记录可信运行与开赛前提交，不能把任意导入的 JSON 当作独立公证。

对某项分数有异议时，保留 run ID、发布摘要、题号、原始 `report.json`、预测文件、verifier 输出与原生轨迹。执行 `./bench report <运行目录> --release datasets/<对应版本>` 重建可读详情，再用发布包内的赛果逐题核对 Brier 与 reward。使用相同后端、版本、模型和预算独立复跑并保留新的 run ID。若发现泄漏，先用 `./bench boundary --out .work/复核目录` 复现并保留攻击命令和证据，修订数据或规则后发布新版本。
