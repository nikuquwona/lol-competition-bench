# 回放榜计分与复现

## 模型与五场对照

首页固定展示五个不同系列赛的五局，每局分别在 BP 前和 BP 后预测。矩阵以模型为行、CLI 为列，单元格可打开原始运行和逐局轨迹。完整比较要求相同发布包、题号、执行后端及协议。部分运行可浏览成功提交的均分与十题覆盖度，正式分母和排名由完整运行产生。一次运行目录和它发布到仓库的副本仅计一次。

「预测运行」收录真实模型交互，包含可审计的未交卷。离线基线、固定响应、隔离验收以及启动失败可在技术记录中查看。免费 OpenRouter 和直连 DeepSeek 分别保留实际模型与收费渠道。

## 比较组

一项参赛配置由原生 CLI 和固定模型标识组成。一次尝试包含一份事先确定的题号清单、每个题号的终态和同一发布包的 SHA-256。榜单按发布版本、归档摘要、排序去重后的题号集合指纹、后端、评测协议和验证方式分组；同系列 BP 前、BP 后是两个题号。

| 赛道 | 纳入范围 |
| --- | --- |
| 受控回放 | 本地证据快照、受限推理网关、确定性评分。DeepSeek 与固定的 OpenRouter 免费模型可以在同一组比较。 |
| 选手历史基线 | `simple` 的离线参照分。 |
| 厂商通道 | 原生 Cursor 厂商服务；本地组织者无法核实其远端工具和上下文。 |
| 协议验收 | 固定回复驱动真实 CLI。分数仅供验证接线。 |

**正式回放榜**要求受控赛道覆盖可信发布包的全部题号。相同题号集合的部分比赛进入独立子集组。基线、厂商、协议验收各自展示。少题、重复题号、仍在执行、清单或分数校验失败的轮次给出排除原因。在新发布包上重新跑一轮即可进入相应版本的比较组。旧报告可缺少轨迹、用量与赛后真值字段；只提供题号集合、无法验证归档真值的旧接口只生成一致性参考组。

## 分母与排序

每题预测蓝方胜率和蓝方 15 分钟领先概率。对每个事件取 `(p−y)²`，单题 reward 为 `1 − (Brier_win + Brier_ahead15)/2`。实际赛果取自可信发布包。服务对已交卷题做输入与题面指纹核验，并从预测、真值重算两个指标。CLI 启动前若隔离预检失败，该轮仅保留为可审计的环境诊断。已开始的试验失败或中断计零。每轮用全部计划题做 reward 分母，同一模型和 CLI 的整轮尝试等权平均。一个组合的 `selected` 与 `scored` 为各轮累计题数。Brier 按全部成功交卷计算，零成功时值为空。

主排序为平均 reward 降序，其次为完成率降序。reward 保留 12 位小数后比较，两个指标都相同则并列，例如 1、1、3。展示全部参与计算的 run ID，默认链接采用字典序第一份。耗时、请求数、重试、token 与费用供复现和效率分析，缺失值为未知；这些值不计入 rank。例：同一两题子集有两次尝试，首次两题各得 0.75，第二次一题得 0.75、一题失败，合计 reward 0.5625，完成率 3/4，Brier 仅对三次成功交卷计算。

## 收录一次新运行

1. 用 `./bench release --version <新版本>` 生成不可变归档和清单，保留原始来源及时间。参赛侧只持有当题快照。历史按先前局号、公开时刻和所选时点截断。lobby 在第一手 BP 公开时关窗，draft-lock 在实际开局时关窗。实盘成绩还需要独立的赛前提交回执，回放榜无法追溯证明模型此前没见过赛果。
2. 在组织者控制的环境执行 `./bench e2e --release datasets/replay-v3 --harness codex --model deepseek-v4-pro`。省略选题条件可跑全量，指定 `--series`、`--game` 或 `--phase` 产生相应子集。记录 CLI 版本、后端、模型 ID、提示词、预算、提供方及可用的用量信息。旧协议归入 `suite-v1`。更改工具权限、上下文或预算时，应为新协议记录独立的 `protocol_sha256` 并保留对应配置。
3. 新 CLI 需接入本仓库受限 worker、完成原生工具轨迹和隐藏标签探测，并使用同一评分器。受控与厂商通道的权限不同，按其实际运行模式注册到对应赛道。不要把 fixture 或供应商代填的预测转换成受控成绩。
4. 将完整输出保留在本地看板扫描范围。检查题号、提交时间、release 归档 SHA-256、快照和题面指纹，以及报告记录的真实模型。重复运行保留独立目录与所有失败，未完成的运行用原配置 `--resume --out <原目录>` 继续。组织者不得删掉低分尝试或复制某轮来改变权重。

## 信任边界与异议复核

本地榜信任组织者、只读发布包和被扫描的运行目录。SHA-256 与重算可以发现错包、错题和算错分，不能证明谁执行了 CLI、模型权重来源、申报者保留了全部尝试，或宿主从未被改写。模型可能记得公开比赛。跨组织正式比赛需另行记录可信运行与开赛前提交，不能把任意导入的 JSON 当作独立公证。

对某项分数有异议时，保留 run ID、发布摘要、题号、原始 `report.json`、预测文件、verifier 输出与原生轨迹。执行 `./bench report <运行目录> --release datasets/<对应版本>` 重建可读详情，再用发布包内的赛果逐题核对 Brier 与 reward。使用相同后端、版本、模型和预算独立复跑并保留新的 run ID。若发现泄漏，先用 `./bench boundary --out .work/复核目录` 复现并保留攻击命令和证据，修订数据或规则后发布新版本。
